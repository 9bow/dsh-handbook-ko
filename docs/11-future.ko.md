# 제 11 장: 미래 전망 —— dsh와 Agent 생태계의 진화 예측

> 본 장의 목표: 여러 각도에서 dsh와 그 생태계의 미래를 추론합니다 —— **기술, 생태계, 경쟁, 산업, 개발자 기회, 리스크**. 예측은 단정이 아니라 "현재 사실을 기반으로 한 추론"이며, 투자할 가치가 있는지 판단하는 데 참고하시기 바랍니다.

## TL;DR(본 장 핵심, 30초 버전)

1. **단기(1-3개월)**: 정식 버전 0.1.0 출시, 플러그인 생태계 폭발, 튜토리얼/도구류 프로젝트가 첫 물결의 보너스를 누림
2. **중기(1년)**: dsh가 "프로그래머블 Agent 베이스"의 사실상 표준 후보가 되고, 버티컬 시나리오 플러그인이 성숙
3. **장기(2-3년)**: Agent 엔지니어링 레이어가 표준화되고, dsh 생태계와 모델 반복이 서로를 성장시킴
4. **최대 리스크**: 파괴적 변경, 생태계 파편화, 공식 전략 전환
5. **개인의 기회**: 지금 진입하는 것(튜토리얼/플러그인/도구)이 저비용 초기 보너스입니다

## 11.1 기술 진화 예측

| 시기 | 예측 | 근거 |
|---|---|---|
| 단기 | `0.1.0` 정식 버전 출시(rc 제거), 파괴적 변경이 수렴됨 | 현재 rc.6, 공식이 "파괴적 변경이 있을 것"이라고 명시, 반복 속도가 매우 빠름 |
| 단기 | 공식이 TUI와 상호작용형 CLI를 보완(커뮤니티 요청이 가장 많음, #172 15+ 댓글) | 공식 Discussion에서 가장 뜨거운 요구사항 |
| 중기 | 캐시/성능 최적화가 주요 테마가 됨(reasoning_effort 세분화, 캐시 적중률 도구화) | 고캐시 적중률이 이미 비용 우위임(제5장), 도구화되어 가시화될 것 |
| 중기 | 플러그인 생태계 표준화(플러그인 마켓/원클릭 설치/품질 등급) | 공식에 이미 `dsh-plugin` topic이 있고, 플러그인 수 증가가 필연적으로 마켓을 촉발 |
| 장기 | Agent 런타임 아키텍처가 "엔지니어링 패러다임"으로 자리잡음(예전 Linux 커널 모델의 Agent 버전과 유사) | "everything is a plugin"이 이미 조합 가능한 아키텍처로 검증됨 |

## 11.2 생태계 발전 예측

- **플러그인 수**: 초일 → 1년 내 예상 수십 개에서 백여 개(비슷한 생태계의 S곡선 참고)
- **콘텐츠 생태계**: 튜토리얼/블로그/awesome 목록이 먼저 폭발(한국어/중국어 콘텐츠는 현재 공백 —— 본 백서가 첫 체계적 튜토리얼)
- **커뮤니티 규모**: 공식 Discussion에 매일 새 토론이 추가되고(하루에 30+ 개의 새 주제를 관찰), Discord 활성도도 동반 성장할 것
- **선두 프로젝트**: 몇 개의 "생태계 플래그십"이 탄생할 것임(VSCode 생태계의 Prettier/ESLint 같은 위상) —— **도구형 + 튜토리얼형이 가장 가능성 높음**

## 11.3 경쟁 구도 예측

| 항목 | dsh 포지셔닝의 진화 |
|---|---|
| vs Claude Code | 단기적으로는 여전히 "바로 사용 가능함이 못 미침", 장기적으로는 "커스터마이즈 가능 + 오픈소스 + 비용"으로 차별화 |
| vs OpenCode | 둘 다 오픈소스; dsh의 공식 백엔드 + 플러그인 생태계가 차별점(OpenCode는 공식 백엔드 없음) |
| vs 자체 구축 프레임워크 | dsh는 "반제품에서 완제품으로 가는 다리" —— 직접 구축보다 편하고, 클로즈드소스보다 제어 가능 |
| 모델 측면 | DeepSeek 모델의 매 세대 반복이 dsh 생태계의 가치를 증폭시킬 것(모델 + 런타임의 시너지) |

**핵심 판단**: dsh의 승부수는 "모델이 얼마나 강한가"(그건 DeepSeek의 몫)가 아니라, **"Agent 엔지니어링 레이어가 표준이 될 수 있는가"**에 있습니다 —— "플러그인을 어떻게 작성하고, 생태계가 어떻게 성장하는지"를 누가 정의하느냐가 이 레이어의 승자를 결정합니다.

## 11.4 산업 응용 예측

- **금융/데이터 분석**: 긴 세션 + 고캐시 적중률 = 비용 친화적인 배치 분석이 가장 먼저 자리잡을 것
- **기업 지식 베이스/문서**: 1M 컨텍스트 + 문서 도구 체인, 기업 내 지식 관리는 자연스러운 시나리오
- **교육**: 배치 문제 출제/해설/정리, 비용에 민감한 시나리오가 캐시의 혜택을 누림
- **버티컬 Agent 제품**: "산업별 Agent 패키징"이 등장할 것임(dsh 위에 산업별 플러그인/설정 팩을 만드는 것)

## 11.5 개발자 기회(지금 진입하는 사람)

| 역할 | 기회 | 시기 |
|---|---|---|
| **튜토리얼/콘텐츠 작성자** | 한국어/중국어 튜토리얼 공백(백서가 첫 번째임) | **지금**(보너스가 가장 큼) |
| **플러그인 개발자** | 공식이 아직 다루지 않은 방향: TUI, 원격 접속, 모바일, 캐시 도구 | **지금** |
| **도구형 프로젝트** | 속도 개선, 소요 시간 시각화, MCP 도구 키트 | 지금(이미 속도 개선 플러그인 실험으로 검증함) |
| **생태계 인프라** | 플러그인 마켓, 템플릿 생성기, 평가 도구 | 중기 |
| **산업 솔루션** | 금융/교육 등 산업 플러그인 팩 | 중기 |

## 11.6 리스크와 불확실성(솔직한 버전)

1. **파괴적 변경**: rc 단계의 API가 자주 바뀔 수 있습니다 —— 플러그인/튜토리얼이 지속적으로 따라가야 합니다(백서도 동기화하여 업데이트할 것입니다)
2. **생태계 파편화**: 플러그인 품질이 들쭉날쭉하고 표준이 부족합니다 —— 초기에는 "고품질 시범 프로젝트"가 필요합니다(본 백서 + 제4장 예제가 그 시범 중 하나입니다)
3. **공식 전략 전환**: 공식이 특정 방향(예: 내장 TUI)을 거둬들일 수 있습니다 —— 생태계 프로젝트는 차별화된 진입 장벽이 있어야 합니다
4. **모델 경쟁**: 다른 모델의 반복이 DeepSeek의 매력을 약화시킬 수 있습니다 —— 하지만 dsh의 모델 독립적 설계(OpenAI 호환 모델도 연결 가능)가 완충 역할을 합니다
5. **인기 하락**: dsh 생태계가 자리잡지 못하면 초기 투자가 "헛수고"가 될 수 있습니다 —— 하지만 튜토리얼/스킬 자체는 이전 가능한 자산입니다

## 11.7 백서 자체의 전망

- **콘텐츠**: dsh의 반복에 맞춰 지속적으로 업데이트(버전 번호를 rc/정식 버전에 맞춤)
- **다국어**: 영어판의 완성도를 중국어판 수준으로 끌어올림
- **사례**: 더 많은 산업 실제 사례(규제 준수 전제하에)
- **생태계**: awesome 목록, 공식 Discussion과 연계해 생태계 콘텐츠 허브 중 하나가 됨

## 11.8 독자에게 드리는 최종 제안

- **한번 해보고 싶다면**: 지금 설치해서 놀아보세요(제2장), 비용은 거의 0입니다
- **투자하고 싶다면**: "공식이 아직 다루지 않았고 + 여러분이 쌓아온 것이 있는" 방향을 고르세요(TUI/산업 플러그인/튜토리얼)
- **관망하고 싶다면**: 0.1.0 정식 버전을 기다리되, 생태계 초기 보너스는 놓칠 것입니다 —— **초기 보너스 ≈ 선점자의 인내심**

> 예측은 틀릴 수 있지만, "지금 진입하는 비용이 가장 낮다"는 사실은 대체로 틀리지 않을 것입니다.

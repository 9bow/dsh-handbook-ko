# 학습 경로: 0부터 1까지 3일 계획

> 약속을 지킵니다: **어떤 개발자든, 3일이면 0부터 플러그인을 개발할 수 있는 수준까지.** 이 경로는 9개 챕터를 3일로 나누며, 매일 명확한 목표와 검수 기준이 있습니다.

## Day 1: 이해 + 실행해보기(제1-2장)

**목표**: dsh가 무엇인지 이해하고, 독립적으로 시작·대화·설정을 할 수 있게 됩니다.

| 시간 | 작업 | 검수 |
|---|---|---|
| 30분 | 제1장 읽기(세 가지 직관 + 능력 매트릭스) | 다른 사람에게 "dsh와 Claude Code의 차이"를 설명할 수 있음 |
| 30분 | 제2장 실습: `dsh web` 대화 + headless | UI를 시작해 대화를 한 번 완료할 수 있음; headless 명령어를 하나 실행할 수 있음 |
| 30분 | 모델/추론 강도 설정 + 트러블슈팅 빠른 참조 | settings.yaml을 수정할 수 있음; 포트 점유를 해결할 수 있음 |

**검수**: `dsh --profile headless "안녕"`에 응답이 있음.

## Day 2: 골격 이해 + 첫 플러그인(제3-4장)

**목표**: profile/플러그인 메커니즘을 이해하고, 실행 가능한 첫 플러그인을 작성합니다.

| 시간 | 작업 | 검수 |
|---|---|---|
| 1시간 | 제3장(profile, 장착, host/client, 확장 포인트, 트러블슈팅) | 커뮤니티 플러그인(Git 패널)을 장착할 수 있음 |
| 1.5시간 | 제4장 예제 속도 개선 플러그인 따라 작성: 순수 함수 + agent/request 주입 | 플러그인이 오류 없이 로드되고, 로그에 결정 출력이 나타남 |

**검수**: 자신이 만든 플러그인이 dsh에서 작동함(로그로 주입이 발생했음을 증명).

## Day 3: 실전 + 튜닝(제5-6장)

**목표**: 플러그인 품질을 평가하고, 성능을 튜닝하며, 생태계 참여 방법을 이해할 수 있게 됩니다.

| 시간 | 작업 | 검수 |
|---|---|---|
| 1시간 | 제5장의 실제 PR 세 가지(안전 레드라인, 샌드박스 제약, 테스트 방법론) | "PR 하나를 작성하는 완전한 폐루프"를 말할 수 있음 |
| 1시간 | 제6장 성능 모델(사고가 90%) + 강도 전략 + 트러블슈팅 | 작업에 맞는 강도를 선택하고 병목을 예측할 수 있음 |
| 30분 | 제8-9장 훑어보기(도구/컨텍스트, MCP/서브에이전트/워크플로우) + 용어집 | dsh의 능력 전체 그림과 확장 방향을 알게 됨 |

**검수**: dsh 생태계에 작은 개선을 기여하거나 사용 후기를 하나 작성할 수 있음.

| 프로덕션 배포 | 공식 아키텍처 문서 + 보안 모델(샌드박스/권한) |
| 성능 극한 튜닝 | 제6장 + 제4장 예제 소스 코드 |
| 생태계 수익화 | 제7장 + dsh-plugin topic |

## 학습 원칙(백서 전체에 걸쳐)

1. **읽기보다 실습**: 매 챕터의 명령어를 직접 한 번씩 실행해보세요, 보기만 하면 후회합니다
2. **먼저 복사하고 나중에 이해하기**: 제4장의 완전한 코드를 먼저 돌려보고, 그다음 파라미터를 바꿔가며 메커니즘을 이해하세요
3. **단위 테스트 + 실기 이중 증거**: 플러그인을 개발할 때는 둘 다 통과해야 합니다
4. **--dump-config를 적극 활용하세요**: 궁금할 때는 합성 설정을 보는 것이 추측보다 빠릅니다

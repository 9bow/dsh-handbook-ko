## 사례 H: 단위 테스트 생성(소프트웨어 엔지니어링 품질 영역)

### 작업 설명

함수 5개가 포함된 합성 모듈 `data_utils.py`(parse_duration / chunk_list / fibonacci / is_valid_email / calculate_interest, 문자열 파싱, 리스트 청크 분할, 수치 재귀, 이메일 검증, 금융 계산을 커버하며, 각 함수마다 의도적으로 설계된 경계와 예외 시맨틱 포함)을 주고, dsh에게 완전한 pytest 단위 테스트(경계와 예외 경로 포함)를 생성해 전부 통과하도록 실행하게 했습니다.

### 입력 산출물

- `data_utils.py`: 함수 5개, 95줄. 시맨틱 요점: parse_duration은 단위 조합/대소문자 구분 없음/잘못된 입력→ValueError; chunk_list는 size≤0→ValueError, int가 아님(bool 포함)→TypeError; fibonacci는 0부터 시작, 음수→ValueError; is_valid_email은 문자열이 아니면→False(예외를 던지지 않음), TLD≥2; calculate_interest는 소수 연도 지원, 음수→ValueError, 초대형 값은 오버플로우로 inf

- **시작**: 2026-08-13T13:11:16-04:00
- **종료**: 2026-08-13T13:13:58-04:00

### 도구 체인 경로(출력에서 추론)

1. `data_utils.py` 읽기, 함수 5개의 시그니처와 예외 시맨틱 파싱(코드 분석 도구)
2. 케이스 매트릭스 설계: 정상 / 경계 / 예외 3방향 커버(의미 이해)

### 검증 결과(100/100 통과)

- **pytest**: `python -m pytest test_data_utils.py -v` → **100 passed, 0 failed**(0.19초)
- **경계 커버리지 대조**: 수동으로 31개 경계를 뽑아 확인 + `python -c`로 20+개 핵심 assert를 검증, 전부 data_utils.py의 실제 시맨틱과 일치하며 모순 없음
  - parse_duration: '1h30m'=5400, '90s'=90, '2d'=172800, '1H30M' 대소문자, None/''/'abc'/'1h30'→ValueError ✓
  - chunk_list: size>len→단일 청크, 빈 리스트→[], size≤0→ValueError, 1.5/True→TypeError ✓
  - fibonacci: 0→0, 1→1, 10→55, 음수→ValueError, int 아님→TypeError ✓
  - is_valid_email: 서브도메인/대문자→True; 빈 문자열/'a@b'/'a b@c.com'/'a@@b.com'/'a@b.c'/문자열 아님→False ✓
  - calculate_interest: (1000,0.05,1)≈1050(approx), rate/years=0 퇴화, 음수→ValueError, 1e308 오버플로우→inf ✓

### 출력 하이라이트

- **케이스 밀도가 매우 높음**: 함수 5개에서 100개 케이스를 만들어냄(함수당 평균 20개), "최소 5개"라는 기준선을 훨씬 뛰어넘으면서도 중복이 없음
- **파라미터화 구성이 우아함**: 같은 유형의 경계 케이스는 모두 `@pytest.mark.parametrize`로 묶고 의미 있는 `ids`를 붙임(`combined_h_m`, `trailing_digits`, `bool_true`), 실패 시 즉시 위치 파악 가능
- **bool 서브클래스 함정을 정확히 커버**: `chunk_list`/`fibonacci`에 각각 `True`/`False`의 TypeError 케이스를 별도로 만들어, 구현의 `isinstance(x, bool)` 사전 검사와 정확히 대응 —— 이것이 초보자가 가장 놓치기 쉬운 Python 타입 함정입니다
- **부동소수점 시맨틱이 정확함**: `calculate_interest` 전체에 `pytest.approx`를 사용하고, `1e308` 오버플로우가 `inf`가 되는 경계 동작을 능동적으로 커버
- **예외 메시지 정밀 매칭**: 다수의 `pytest.raises(..., match="must be ...")`로 예외 타입과 메시지 텍스트를 동시에 검증, 타입만 잡는 것이 아니라서 테스트의 견고성이 높음

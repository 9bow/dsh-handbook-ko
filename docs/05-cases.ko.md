# 제 5 장: dsh가 당신을 도울 수 있는 것 —— 활용 시나리오 전체 조망

> 본 장의 목표: "dsh를 어떻게 개발하는가"의 관점을 잠시 내려놓고, **사용자**의 관점에서 dsh가 어떤 일상 시나리오에서 실제로 도움이 되는지 살펴봅니다. 각 시나리오마다 그대로 따라 할 수 있는 작업 예시와 실제 소요 시간 참고자료를 제공합니다.

## TL;DR(본 장 핵심, 30초 버전)

1. **dsh는 범용 Agent 런타임입니다**: 코딩 어시스턴트에 그치지 않습니다 —— 데이터 분석, 문서 생성, 자동화, 코드 이해까지 모두 가능합니다
2. **다섯 가지 핵심 시나리오**: 일상 코딩 / 데이터 처리 / 문서 지식 작업 / 자동화 운영 / 코드 이해와 리팩터링
3. **일관된 사용법**: 한 문장으로 목표를 설명하고 검수 기준을 명확히 쓰면, dsh가 자동으로 도구 체인을 오케스트레이션해 완료합니다
4. **실제 속도**: 단순 작업은 초 단위, 복잡한 다단계 작업은 1-5분(V4-Flash + high 강도 실측)
5. **프롬프트 황금률**: dsh에게 "완료의 기준이 무엇인지"를 알려주는 것(예: "실행 검증 통과")이 과정을 설명하는 것보다 효과적입니다

## 5.1 시나리오 개요

| 시나리오 | 전형적인 작업 | dsh의 도구 | 실측 참고 |
|---|---|---|---|
| **일상 코딩** | 함수 작성, 버그 수정, 테스트 보완 | write / read / bash / grep | 5개 버그 수정+49개 테스트: 94초 |
| **데이터 처리** | 정제, 분석, 시각화, 리포트 | read / write / bash / python | 데이터 정제+시각화: 186초 |
| **문서 지식** | API 문서, 튜토리얼, 요약, 번역 | read / write | API 문서 생성: 1분 04초 |
| **자동화 운영** | 배치 처리, CI 작업, 로그 분석 | bash / headless | headless 스크립트화 |
| **코드 이해** | 리팩터링, 리뷰, 기술 조사 | grep / glob / read / bash | 코드 리팩터링: 4분 37초 |

> 모든 실측치는 백서 제10장의 실제 사례(합성 데이터)에서 가져왔습니다. 자세한 내용은 [benchmark](./benchmark.md) 참고.

## 5.1.1 고캐시 적중률: dsh의 비용 비밀 무기

**이것은 dsh 생태계에서 가장 저평가된 장점입니다**. DeepSeek API의 **context cache**(프롬프트 캐시): 반복/유사한 입력 토큰은 캐시 가격으로 과금됩니다. 실측(실제 dsh 세션 통계) 결과 **캐시 적중률이 97%에 달합니다**.

**왜 dsh의 캐시 적중률이 특히 높은가**:

| 이유 | 설명 |
|---|---|
| 세션 연속성 | 같은 세션에서 여러 라운드 대화 시, 시스템 프롬프트/스킬 카탈로그/이력이 반복됨 → 적중 |
| 안정적인 도구 스키마 | 매 단계 요청마다 동일한 도구 정의를 전달함 → 적중 |
| Agent 워크로드 특성 | 다단계 도구 체인이 반복적으로 동일한 컨텍스트를 전달함 → 적중률이 자연히 높음 |

**비용에 미치는 영향(98% 캐시 할인)**:

| 과금 항목 | 미적중 가격 | 캐시 적중 가격 | 할인율 |
|---|---|---|---|
| 입력(Flash) | $0.14/M | **$0.0028/M** | **98%** |
| 입력(Pro) | $0.435/M | $0.003625/M | 99%+ |

**실질적 의미**: 긴 세션의 Agent 작업에서는 대부분의 입력 토큰이 캐시 가격으로 처리됩니다 —— **실측에서 "50단계 도구 체인 작업, 240만 입력 토큰"의 비용이 미적중 가격 기준 예상치보다 훨씬 낮았습니다**. 고빈도/배치/긴 세션 시나리오에서는 이것이 자릿수 단위의 비용 우위입니다.

> 캐시 적중률을 더 높이는 방법: **세션 연속성 유지**(자주 새 세션을 열지 마세요), **prompt 접두사 안정화**(시스템 프롬프트/스킬 카탈로그를 자주 바꾸지 마세요), 배치 작업은 같은 세션/같은 접두사에 두세요.

## 5.2 시나리오 1: 일상 코딩(입문에 가장 적합한 시나리오)

**전형적인 작업**:
- 요구사항에 따라 새 함수/모듈 작성
- 버그 수정(위치 찾기 → 수정 → 검증)
- 단위 테스트 보완

**작업 예시**(headless 원클릭 실행):

```bash
dsh --profile headless "buggy_calculator.py를 검토해: 모든 버그를 찾아 수정하고, 완전한 테스트를 작성하고, 실행해서 전부 통과하는지 검증해"
# 실측: 5개 버그 전부 수정 + 49개 테스트 통과(94초)
```

**dsh가 적합한 이유**: 코딩은 도구 체인이 가장 완결된 시나리오입니다 —— 파일 읽기, 코드 작성, 명령 실행, 결과 확인이 매끄럽게 폐루프를 형성합니다. 산출물(수정된 파일)은 대화 끝에서 바로 열어볼 수 있습니다.

**프롬프트 팁**: 반드시 "실행 검증"을 써야 합니다 —— dsh는 그대로 폐루프를 완성합니다; "버그 수정 도와줘"만 쓰면 수정만 하고 멈춥니다.

## 5.3 시나리오 2: 데이터 처리와 분석

**전형적인 작업**:
- 데이터 품질 점검과 정제
- 통계 분석
- 시각화(차트)
- 분석 리포트 생성

**작업 예시**:

```bash
dsh --profile headless "sales_data.json의 데이터 품질을 분석해(결측/타입 오류/중복/이상치), 정제 스크립트+시각화 스크립트를 작성하고, 실행 검증한 후 처리 방안을 요약해"
# 실측: 52→35줄로 정리 + 차트 + 트레이드오프 설명(186초)
```

**하이라이트**(실측): dsh는 실행만 하는 게 아니라 **트레이드오프를 설명**합니다 —— "중위수로 채우면 스파이크가 생길 수 있음", "이상치를 삭제할지는 비즈니스에 달려 있음" —— 이것이 agent 엔지니어링 레이어가 "생각한다"는 직접적인 증거입니다.

## 5.4 시나리오 3: 문서와 지식 작업

**전형적인 작업**:
- 코드에서 API 문서 생성
- 노트를 구조화된 문서로 정리
- 긴 글 요약, 번역

**작업 예시**:

```bash
dsh --profile headless "user_module.py(함수 8개)에 대한 완전한 Markdown API 문서를 생성해: 파라미터 표, 반환값, 예외, 예시, 경계 상황 포함"
# 실측: 423줄 ReadTheDocs 스타일 문서(1분 04초), "문서 계약 vs 코드 구현" 차이를 능동적으로 식별
```

**하이라이트**(실측): dsh는 **방어적 글쓰기**를 합니다 —— 호출 함정을 표시하고(음수 limit의 동작, 빈 파라미터의 동작), 문서 선언과 구현이 일치하지 않는 부분을 발견하면 있는 그대로 설명합니다.

## 5.5 시나리오 4: 자동화와 운영(headless가 필살기)

**전형적인 작업**:
- 매일 정해진 시간에 데이터 작업 실행(일일 리포트, 모니터링 요약)
- 배치 파일 처리(이름 변경, 형식 변환)
- CI에서의 자동화 검사

**작업 예시**(스크립트화):

```bash
# cron으로 매일 8시에 일일 리포트 생성
dsh --profile headless "워크스페이스의 git log를 읽고 한국어 일일 리포트를 생성해" > daily-report.md

# 배치 처리: 디렉터리 안의 모든 .txt를 .md로 변환
dsh --profile headless "docs/ 아래의 모든 .txt를 .md로 변환해(구조 유지)"
```

**headless가 필살기인 이유**: 프로세스 레벨 도구(bash/파일/검색)를 전부 사용할 수 있음 + 0이 아닌 종료 코드가 곧 실패 + 출력을 파이프로 처리 가능 —— **이것은 "CI에 넣을 수 있는 Agent"입니다**.

## 5.6 시나리오 5: 코드 이해와 리팩터링

**전형적인 작업**:
- 절차형 코드를 OOP로 리팩터링
- 전체 저장소 코드 리뷰
- 기술 조사("이 모듈은 어떻게 동작하는가")

**작업 예시**:

```bash
dsh --profile headless "legacy_orders.py를 객체지향+책임 분리 구조로 리팩터링해, 동작은 그대로 유지하고, 리팩터링 전후 출력이 같은지 테스트로 검증해"
# 실측: 17/17 테스트 통과, 스크립트 레벨 산출물 비교 포함(4분 37초)
```

**하이라이트**(실측): dsh의 엔지니어링 인식 —— 중복 코드를 식별해 단일 진입점으로 병합, 하위 호환성 유지, **샌드박스에서 tempfile 권한 문제를 발견하고 능동적으로 방안을 변경**.

## 5.7 시나리오를 현실화하는 세 가지 프롬프트 법칙

1. **검수 기준을 쓰고, 과정을 쓰지 마세요**: `"실행 검증 통과"` > `"스크립트 하나 작성해줘"` —— dsh가 스스로 단계를 오케스트레이션합니다
2. **컨텍스트를 주세요**: 배경을 한 문장으로 명확히 설명하세요(파일이 어디 있는지, 데이터가 어떻게 생겼는지, 목표 독자가 누구인지)
3. **한 번에 하나의 작업**: 복잡한 목표는 여러 라운드로 쪼개는 것이(라운드마다 하나의 작은 폐루프) 한 번에 거대한 작업을 주는 것보다 더 신뢰할 수 있습니다

## 5.8 나의 첫 실제 작업(15분 시작하기)

1. 테스트 디렉터리를 하나 만들고, 손에 있는 작은 파일(코드/데이터/노트)을 하나 넣으세요
2. 실행: `dsh --profile headless "이 파일을 요약하고, 개선할 수 있는 3가지를 짚어줘"`
3. 실행: `dsh --profile headless "이 파일에 대한 테스트를 작성하거나/문서를 생성해줘"`
4. 출력을 비교하며 dsh의 "완성도"를 체감해보세요 —— 대략적인 것만 준 건 아닌가요? 검수 기준을 명확히 썼나요?

## 자주 묻는 질문(FAQ)

- **Q: dsh는 코딩 어시스턴트일 뿐인가요?** 아닙니다 —— 도구 체인(읽기/쓰기/실행/검색)이 범용성을 만들어줍니다. 데이터 처리/문서/자동화 모두 검증되었습니다
- **Q: 복잡한 작업은 얼마나 걸리나요?** 실측 1-5분(V4-Flash); 더 빠르게 하려면 추론 강도를 낮추세요(제6장)
- **Q: 작업이 실패하면 어떻게 하나요?** 출력의 도구 호출 트레이스를 보고 원인을 찾으세요; 대부분은 "검수 기준이 불명확"한 경우이니, 프롬프트를 다시 써서 재실행하세요
- **Q: 자동으로 실행할 수 있나요?** 가능합니다 —— headless + 0이 아닌 종료 코드 + 파이프 출력으로 cron/CI에 넣을 수 있습니다
- **Q: 안전한가요?** 도구 실행에는 샌드박스와 승인 레이어가 있습니다; 민감한 작업은 사람의 확인을 권장합니다(제8장 보안 모델)
- **Q: Claude Code를 직접 쓰는 것과 무엇이 다른가요?** 같은 모델이라면 능력은 비슷하지만, dsh는 도구 체인/인터페이스/플러그인을 커스터마이즈할 수 있습니다(제1장 매트릭스 참고)

## 5.9 산업 관점: dsh가 서로 다른 영역에서 활용되는 방식

> 같은 도구 체인이지만 산업마다 사용법이 다릅니다. 아래는 범용 시나리오입니다(실제 비즈니스 데이터 미포함), 규제가 민감한 영역(의료/법률)은 반드시 사람이 직접 검토하세요.

### 금융과 투자 리서치
- **작업**: 재무제표 요약, 리서치 보고서 핵심 추출, 팩터 설명 문서, 투자 메모
- **예시**: `dsh --profile headless "이 재무 데이터를 읽고, 전년 대비/전분기 대비 변화가 포함된 요약 리포트를 생성해"`
- **dsh의 장점**: 데이터 처리 파이프라인이 손에 익음 + 고캐시 적중률(긴 리포트 세션이 저렴함)

### 교육과 학습
- **작업**: 교안 생성, 문제 풀이, 오답 정리, 학습 계획
- **예시**: `dsh --profile headless "이 챕터의 지식 포인트를 자가 테스트 문제 10개로 정리해줘(해설 포함)"`
- **dsh의 장점**: 문서 생성 + 구조화가 강점, 배치로 문제 출제/정리 가능

### 영업과 고객 서비스
- **작업**: FAQ 정리, 스크립트 생성, 고객 피드백 분류
- **예시**: `dsh --profile headless "고객 피드백 100건을 문제 유형별로 분류하고 개선 제안을 제시해줘"`
- **dsh의 장점**: 배치 텍스트 처리 + 분류 정리

### 운영과 콘텐츠
- **작업**: 주간/월간 리포트, 데이터 대시보드 설명, 콘텐츠 주제 선정, SEO 요약
- **예시**: `dsh --profile headless "이번 주 데이터 파일을 읽고 운영 주간 리포트를 생성해줘(차트 코드 포함)"`
- **dsh의 장점**: 데이터 + 문서 + 자동화의 조합

### 연구와 리뷰(학술/기술)
- **작업**: 논문 핵심 추출, 기술 조사, 문헌 비교
- **예시**: `dsh --profile headless "이 논문 3편의 방법론과 결론을 비교해서 비교표를 출력해줘"`
- **dsh의 장점**: 긴 문서 처리 + 구조화된 출력(1M 컨텍스트)

### ⚠️ 규제 준수 안내
의료 진단, 법률 의견, 재무 자문 등 **고위험 시나리오**에서는: dsh의 출력을 반드시 사람이 검토해야 하며, 의사결정에 직접 사용할 수 없습니다 —— 도구 실행에는 샌드박스가 있지만, **콘텐츠에 대한 책임은 사용자에게 있습니다**.

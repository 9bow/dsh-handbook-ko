# 제 15 장: DSH 생태계 전체 리포트 —— 4000+ 플러그인과 2400개 디스커션 스레드가 말해주는 것

> 본 장의 목표: **커뮤니티 데이터 집계(4000+ 플러그인, 플러그인 스토어 dsh-hub.cc 등재 포함)**와 **본 핸드북의 2400+개 디스커션 스레드 관찰 + 225개 게시물 응답 경험**을 교차 검증해, dsh 생태계의 전체 그림을 그립니다 —— 어디가 폭발적으로 성장하는지, 어디에 공백이 있는지, 기회는 어디에 있는지.
> 데이터 출처: Blue-Whale-Harness 플러그인 전체 목록(커뮤니티 유지, 2026-08 수집 1804개 저장소) + 플러그인 스토어 [dsh-hub.cc](https://dsh-hub.cc)(4000+ 등재, 2026-08 오픈); 디스커션 관찰은 2026-08 기준(스레드 번호 2400+).

## TL;DR(30초 버전)

1. **생태계가 폭발하고 있습니다**: 4000+개 플러그인(플러그인 스토어 dsh-hub.cc 등재), 2주 만에 무에서 성장; 디자인/UI 생성(348개/94K★)과 비전(132개/90K★) 수요가 가장 뜨겁습니다
1b. **유통의 질적 변화**: 플러그인 스토어 오픈(#2423) —— awesome 목록에서 검색·게시 가능한 스토어로 업그레이드, 생태계가 "야생 성장"에서 "질서 있는 유통"으로 진입
2. **"공식이 안 하면 커뮤니티가 다 한다"가 주요 테마입니다**: 데스크톱 쉘(140+), TUI, 기억, 비전 브리지가 전부 커뮤니티가 채운 것입니다
3. **공백이 명확합니다**: 금융(8개), 데이터베이스(14개), 오디오(19개), 평가(37개)는 거의 공백입니다 —— 하지만 수요는 존재합니다
4. **Windows와 원격은 아픈 지점입니다**: 중국어 경로 계열(#107 등 15+개 스레드), 자식 프로세스(#717), LAN RPC(#755)
5. **차별화 베팅 포인트**: 전체 session log + 모든 것이 플러그인 + 샌드박스/권한 체계 → 기업/평가/규제 준수 시나리오

## 15.2 정성적 인사이트(780개 스레드 디스커션 관찰, 교차 검증 데이터)

### 인사이트 1: Windows가 가장 큰 페인 포인트(60+개 스레드)

데이터 측면: Windows 호환성이 가장 고빈도 주제; 디스커션 측면: **중국어 경로 절단(#107/#151/#396/#800 등 15+개 스레드가 같은 근본 원인)**, koffi 네이티브 크래시(#197/#293), 포트 예약 구간(#589), 자식 프로세스 우아한 종료 부재(#717), 샌드박스 임시 디렉터리 정리 시 크래시(#758).

**교차 검증**: 데이터 측면의 "Windows 호환성 부족"과 디스커션 측면의 60+개 스레드가 완전히 서로를 입증합니다 —— **이것이 가장 확실한 생태계 약점입니다**.

### 인사이트 2: "공식이 안 하면 커뮤니티가 다 한다"

데이터 측면: 데스크톱 쉘 140+, TUI 여러 세트, 기억 77, 비전 132; 디스커션 측면: 2주 만에 커뮤니티가 CLI/TUI/데스크톱/memory/비전을 보완(#391/#405/#386 등).

**교차 검증**: 공식(0.1.0-rc 단계는 코어에 집중)과 커뮤니티(생태계 공백을 채움)가 건강한 상호 보완을 형성합니다 —— **이것이 생태계 활력의 가장 강력한 신호입니다**.

### 인사이트 3: 보안 감사가 이례적으로 활발함

데이터 측면: **sandbox 카테고리 플러그인이 단 9개**(보안 도구 희소); 디스커션 측면: 보안 감사 게시물이 밀집(#243/#250/#278/#381/#454/#774/#817 체계적 감사; vm 탈출/approval 순환 참조/clickjacking 실제 발견) + 보안 도구 체인(vetting/egress-guard/read-confine/check-dsh-profile).

**교차 검증**: 보안 수요는 높지만(감사가 활발함) 보안 도구는 적습니다(sandbox 플러그인 9개) —— **공급 공백**입니다.

### 인사이트 4: 직렬화/경계 버그 계열이 집중적으로 터짐

디스커션 측면: unknown tool ""(#725/#1405), reasoning 직렬화 생략(#739/#1850), 잘린 tool-call 오염(#1519), run_code 비동기 콜백 유실(#1476), 손상된 세션이 boot를 끌어내림(#1473/#1497) —— **전부 llm-deepseek 직렬화 레이어/세션 상태 머신의 경계 문제입니다**.

**판단**: rc 시기 이 레이어의 버그가 집중되는 것 = 공식의 다음 반복 사이클에서 주요 전장이며, 커뮤니티 패치/수정 브랜치의 노다지이기도 합니다(#1519/#725 모두 테스트 수정을 포함).

### 인사이트 5: 비용 투명화는 숨은 필수 수요

데이터 측면: 콘텐츠 창작 40개/88K★; 디스커션 측면: token 소비/캐시 적중 토론이 밀집(#735/#1052/#1234/#1374/#1520), 비용 도구가 우후죽순처럼 등장(dsh-usage/usage-panel/Show Me How Much/balance-meter).

**교차 검증**: 캐시 적중 97%(실측)는 비용 우위지만 "보이지 않습니다" —— 비용 도구가 "통계"에서 "엔지니어링"으로(제14장) 나아가는 것이 확실한 방향입니다.

### 인사이트 6: 플러그인 스토어 오픈 —— 유통이 "목록"에서 "스토어"로(신규)

데이터 측면: dsh-hub.cc가 **4000+개 플러그인**을 등재(2026-08 오픈, 검색 가능/카테고리별 게시 가능); 디스커션 측면: #1825 "플러그인 마켓을 플러그인으로 만들자" 제안 + #2423 스토어 오픈 —— **커뮤니티가 2주 만에 공식이 만들지 않은 유통 인프라를 채웠습니다**(데스크톱 쉘/TUI와 같은 "공식이 안 하면 커뮤니티가 다 한다"는 라인).

**교차 검증**: 플러그인 총량이 1804(전체 목록)에서 4000+(스토어)로 늘었습니다 —— 기준이 다르지만(스토어는 일부 진짜가 아닌 플러그인도 포함), 규모 변화는 생태계가 여전히 지수적으로 성장하고 있음을 보여줍니다.

### 인사이트 7: 오디오/멀티모달 능력 공백이 공식적으로 제안됨(신규)

데이터 측면: 오디오류 플러그인은 여전히 희소함(19개); 디스커션 측면: #2008 실시간 음성 + #2431 ASR/TTS/avatar 능력 공백 표준 제안 —— **오디오가 "커뮤니티 플러그인"에서 "표준 능력 공백"으로 넘어가고 있습니다**(비전 #2024 core 구현과 같은 길).

**판단**: 공식이 표준을 정하고 커뮤니티가 구현을 채우는 패턴이 비전/오디오 두 모달리티에서 재현되고 있습니다 —— 이것이 생태계가 "공백 채우기"에서 "표준화"로 넘어가는 전환 신호입니다.

## 15.4 생태계 참여자를 위한 제안

### 여러분이 플러그인 개발자라면
1. **공백 우선**: 금융/데이터베이스/오디오/평가는 블루오션입니다(경쟁자가 적고 수요가 확실함)
2. **보안 도구가 희소함**: sandbox 카테고리는 9개뿐 —— 보안/권한/감사류 플러그인의 공급이 부족합니다
3. **비전/기억이 핫스팟**: 하지만 경쟁이 치열하므로, 차별화(버티컬 시나리오/기업)가 트렌드를 따라가는 것보다 낫습니다

### 여러분이 도구를 선택 중이라면
1. **차별화 베팅 포인트**: 전체 session log + 모든 것이 플러그인 + 샌드박스/권한 → **기업/평가/규제 준수 시나리오**(데이터/디스커션 이중 검증의 우위 영역)
2. **리스크 포인트**: Windows/원격 시나리오는 현재 아픈 지점입니다, 팀이 Windows 위주라면 평가가 필요합니다
3. **비용 우위**: 캐시 적중 97% × 할인, 비용 투명화 도구 체인이 이미 갖춰짐(제14장)

### 여러분이 관망 중이라면
- **생태계 초기 보너스가 여전히 있습니다**: 4000+개 플러그인이지만 버티컬 영역(금융 8/데이터베이스 14/오디오 19)은 여전히 거의 공백입니다 —— 스토어 오픈이 오히려 "공백 찾기"를 쉽게 만들어, 진입 기간이 명확합니다
- **선점자의 인내심**: 공식 rc 반복이 빨라, 능력 공백은 계속 나타날 것입니다

## 15.5 본 리포트의 방법론 안내

- 데이터 측면(1804개 저장소 전체 목록 + 4000+ 스토어 등재)의 기준은 이미 명시했습니다(README에 dsh가 언급됨, 일부 진짜가 아닌 플러그인 포함) —— **방향성 참고이지, 정밀한 통계가 아닙니다**
- 정성적 측면(2400+개 스레드 + 225개 게시물 응답)은 본 핸드북의 지속적인 관찰에서 나왔습니다 —— 스레드 번호는 모두 추적 가능합니다
- 두 측면을 대조해, "데이터와 디스커션이 모두 가리키는" 부분을 결론으로 채택해 한쪽으로 치우친 편향을 줄였습니다

> 생태계는 계속 변하고 있으며, 본 리포트도 디스커션에 맞춰 지속적으로 업데이트될 것입니다([반영 파이프라인](./research/feedback-pipeline.md) 참고).
